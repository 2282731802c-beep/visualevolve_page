Abstract

Visual tool use enables vision-language models (VLMs) to acquire task-relevant evidence, but its effectiveness can be limited by predefined visual operations and the tool-use strategies learned during training. Representing these operations and strategies as reusable external skills allows them to be refined through self-evolution without updating model parameters. However, skill refinement can introduce performance regressions. Meanwhile, inspecting accumulated task execution trajectories together with skill evolution history may lead to evolution evidence overload. To address these challenges, we propose VisualEvolve, a self-evolving framework that evolves executable visual operations and tool-use strategies for VLMs through a Select–Execute–Evolve–Evaluate cycle. Skill-Library Snapshot Selection uses performance on a fixed validation set disjoint from execution tasks to select an effective historical snapshot for subsequent evolution, limiting the propagation of performance regressions. Progressive Evidence Access (PEA) guides capability-gap diagnosis through a coarse-to-fine hierarchy comprising the Skill-Performance Report, Evolution Log, Trajectory Summaries, and relevant raw trajectory segments. Across four VLM backbones and six evaluation sets from three benchmarks, VisualEvolve improves over the Initial Skill Library in 23 of 24 settings, with a maximum gain of 15.1 percentage points on VisualProbe Hard using Qwen3.5-Plus. Ablation studies support the contributions of Snapshot Selection and PEA, while further experiments show that skills can be improved using experience from different data settings and directly reused across backbones. Moreover, VisualEvolve enables effective skill self-evolution with over an order of magnitude fewer task-solving trajectories than estimated for representative RL-based methods.

Framework Overview

VisualEvolve evolves a skill library through multi-round Select–Execute–Evolve–Evaluate cycles. Skill-Library Snapshot Selection chooses the starting skill library, Execute applies it to the execution set to collect execution evidence, Evolve diagnoses capability gaps and updates the skill library, and Evaluate assesses and archives the updated skill library.

To limit the propagation of performance regressions, Skill-Library Snapshot Selection guides the agent to choose a starting library from archived snapshots based on validation performance.

Ablation Study

Framework stages. All three framework stages contribute substantially to multi-round skill evolution. Removing Skill-Library Snapshot Selection, Execute, or Evaluate reduces macro-average accuracy by 5.4, 7.7, and 6.4 percentage points, respectively. In particular, w/o Execute reaches only 61.5% best-so-far validation accuracy, highlighting the importance of execution evidence for effective skill updates.

Progressive Evidence Access. The ablations support the effectiveness of the coarse-to-fine evidence-access mechanism. Removing any individual PEA component reduces macro-average accuracy by 2.6–4.6 percentage points. Jointly removing the Skill-Performance Report and Evolution Log reduces accuracy by 5.8 percentage points, while removing PEA entirely reduces accuracy by 6.3 percentage points.

Generalization

(a) Evolution-data sources. VisualEvolve consistently improves macro-average accuracy across all three evolution-data sources, with gains of 8.8, 7.1, and 5.0 percentage points over the Initial Skill Library under Default, Mini-o3, and CodeVision, respectively. These results support the robustness of skill evolution across the data sources.

(b) Cross-backbone transfer. The skill library evolved with Kimi-K2.5 is reused without modification and improves over the Initial Skill Library on all three other backbones. Its macro-average accuracy is only 2.7, 1.4, and 1.1 percentage points below backbone-specific evolution on Qwen3.5-Plus, Qwen3.6-Plus, and Doubao-Seed-2.0-Pro, respectively, retaining most of the performance gains from backbone-specific evolution.

Cost Analysis

(a) Trajectory budget. VisualEvolve uses 3,912 Worker task-solving trajectories, whereas the training-based baselines use an estimated 63–209× as many RL trajectories.

(b) Evolution cost. The mean API cost of each evolution round is $2.55–$4.12 across the evaluated backbones.

(c) Inference overhead. The evolved skill library consistently improves accuracy with only modest additional inference cost. On VisualProbe Hard, an additional cost of $0.0268 per example improves accuracy by 15.1 percentage points over the Initial Skill Library, using Qwen3.5-Plus.

Using VisualEvolve

Run skill evolution with your choice of model by updating the model and API settings. To adapt to a new domain, prepare domain-specific data, initial skills, and task instructions.

Same domain, a different model.

Switch the task-solving model through configuration.

  1. 01

    Choose the task-solving model

    Set worker_model to the model ID supplied by your API provider. Choose a model that supports the target task’s inputs and tool use.

  2. 02

    Connect the API

    For a new provider, update base_url and api_key_env, set compatible model IDs for the agent roles, and add the required API keys to .env.

  3. 03

    Run skill evolution

    Create a configuration from the released defaults, then run the same evolution entry point with the new configuration.
